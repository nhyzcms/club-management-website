# 统一数据根（data root）

> 站点全部**持久数据**（用户上传、私有材料等）统一存放在「数据根」下：位置可配置、可整体迁移，应用代码不感知物理位置。
> 启用：2026-10-16（生产 `/opt/club/data`）。

## 1. 结构

```
<数据根>/                     # 生产：/opt/club/data（安装目录内）
├── media/                    # 公开上传 → nginx /media/（对外 URL 不变）
├── private_media/            # 身份证明等 → 鉴权视图（绝不经 nginx 公开）
└── app-update/               # App 更新分发 → nginx /app-update/
```

## 2. 配置

- 环境变量 **`CLUB_DATA_DIR`**（写进 `.env`）：数据根的**实际位置**。
  - 缺省（未配置 / 留空）= 安装目录本身 → 历史布局（`<安装目录>/media` 等），行为不变；
  - 推荐绝对路径（相对值按安装目录锚定）。
- 派生关系（`config/settings.py`；媒体路径全部自动跟随，无需另行修改）：
  - `MEDIA_ROOT = <根>/media`
  - `PRIVATE_MEDIA_ROOT = <根>/private_media`
- Nginx **不读**应用配置：其别名引用安装目录下的「稳定名义路径」（见 §4）。

## 3. 章程（开目录规则）

1. **新目录一律开在数据根下**（扁平一层），不开新的顶层目录——顶层目录受更新器同步管辖，不在豁免名单里、又不在 release 包里的会被更新删除；
2. **公开性归 nginx 管**：URL 与物理路径解耦；物理结构不对外暴露，公开目录才在 nginx 里加 `location`；
3. **根内只放「值得备份的持久数据」**：可重建产物（`staticfiles/`、`.venv/`、`run/`）与备份产物（`backups/`）不进根——保持「备份 = 数据根 + 数据库」的干净语义。

### 目录登记表（开新目录时同步登记）

| 目录 | 用途 | 服务方式 | 是否备份 |
|---|---|---|---|
| `media/` | 头像、新闻图、活动图、教程、附件、全景图等 | nginx `/media/` | 是 |
| `private_media/` | 身份证明（IdentityProof） | 鉴权视图（不进 nginx） | 是 |
| `app-update/` | App 分发（manifest.json / latest.apk） | nginx `/app-update/` | 是 |

### 开新目录 5 步

1. 建目录：`mkdir <根>/<名字>`（属主与相邻目录保持一致）；
2. 定公开性：公开 → 第 3 步；私有 → 由带鉴权的视图提供，跳过第 3 步；
3. （公开时）nginx 加 `location`：`alias <根>/<名字>/;`，`nginx -t && systemctl reload nginx`；
4. （应用需要时）`config/settings.py` 中从 `DATA_DIR` 派生新路径常量；
5. 更新本文档「目录登记表」。

## 4. 换根剧本（换盘 / 换位置）

数据根位置变化时**代码一行不改**，迁数据 + 同步引用点即可：

1. 维护窗口：`sudo systemctl stop club`（避免迁移中写入）；
2. 搬迁：同盘 `mv <旧根> <新根>`（秒级）；跨盘用 `rsync -a <旧根>/ <新根>/`，校验后删旧；
3. 改配置：`.env` → `CLUB_DATA_DIR=<新根>`；
4. **nginx 引用点**：nginx 引用的是安装目录下的「稳定名义路径」（生产为 `<安装目录>/data`）。二选一：
   - a）新根仍位于安装目录内（如挂载点场景）：无需动 nginx；
   - b）新根在安装目录之外：确认数据已在新根后，将名义根替换为软链——`sudo rm <安装目录>/data && sudo ln -s <新根> <安装目录>/data`——nginx 别名与更新器豁免均不需改动；
5. 启动验证：`systemctl start club`；抽查公开图片 / 私有鉴权 / app-update；传 1 张图确认新写入落在新根；
6. 记录：运维手册留档（日期、旧根 → 新根、验证结果）。

> **更新器豁免**：`common/updater.py` 的 `SYNC_EXCLUDES` 含顶层名 `"data"`——数据根位于安装目录内时不会被更新流程触碰；位于安装目录外时天然无关。

## 5. 与备份的关系

「备份 = **数据根整体打包** + 数据库导出」。备份产物（快照）放安装目录的 `backups/` 下，**不属于数据根**；异地副本策略见运维手册。
