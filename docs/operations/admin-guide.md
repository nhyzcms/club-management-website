# 后台管理手册

面向运营与管理员：登录 Django admin，管理用户与认证、审核队列、新闻、活动与问卷、任务、教程、招生、考试看板、关于页、校园全景图、横幅公告与站点策略。本文只写「后台能做什么、怎么做」，逐项接口契约见 [API 文档](../api/README.md)。

> 相关：[部署与运维指南](deployment.md)（服务、更新、备份）、[访问控制原则](../adr/0005-access-control-principle.md)（权限而非组名）、[统一审核系统](../adr/0017-unified-moderation-system.md)（三套案件、一个入口）

## 1. 登录与入口

1. 浏览器打开站点，访问 `/admin/`（例如 `https://club.example.com/admin/`）。
2. 用管理员账号登录（账号由部署时的 `install.sh` 创建，或运维用 `createsuperuser` 补建）。

后台登录与门户共用同一套限流：登录**失败**按 IP（默认 30 次/小时）与按用户名 / 邮箱（默认 10 次/小时）双维度计数，命中返回 429 与 `Retry-After`；同账号已有未满 10 分钟的当前会话时，另一处登录会返回 409 `login_protection`。额度在「站点策略」里调整。

**权限从哪来**：后台可见模块与可执行动作都由 Django 权限（`has_perm`）决定，**不是**看组名。安装脚本会播种两个默认组作为起始包：

| 默认组 | 默认持有（播种自各 app 的迁移） |
|---|---|
| `信息组` | `news.add_news` / `change_news` / `delete_news`（经迁移 0009 归一为 `news.manage_news`）、`about.change_aboutpage` → `about.manage_aboutpage`、`exam_board.add_exam` / `change_exam` / `delete_exam` → `exam_board.manage_exams`、`messaging.manage_announcement` |
| `社长` | `tasks.manage_tasks` / `assign_task` / `manage_tags`、`reviews.moderate`、`reviews.read_feedback`、`reviews.handle_report`、`accounts.can_review_identity`、`activities.review_collection`、`messaging.mute_user` / `manage_comment_thread` |

组只是「权限束」的便利容器：可改名、可删除、可另建组，鉴权代码只认权限代号。超级用户隐式持有全部权限（唯一逃生舱）；`is_staff` 只决定「能否登录 admin」，在业务接口里零权限。

**给成员开权限**：`认证和授权 → 用户` → 选中用户 → 编辑「权限」与「组」。不给任何权限也能登录门户，只是写操作（发帖 / 私信 / 建申报等）需要账号「已认证」。

## 2. 用户与认证

### 2.1 用户（`认证和授权 → 用户`）

用户列表显示用户名、邮箱、名、姓、`is_staff`、`is_active`、已注销，可按 `is_staff` / `is_active` / 已注销过滤、按用户名 / 邮箱 / 姓名搜索。用户编辑页内嵌 `Profile` 内联表单（头像、昵称、生日、性别、简介、真实姓名、身份、邮件转发开关）与**认证通道**表（通道 / 状态 / 标识 / 通过时间 / 有效期至——「有效期至」可由持 `accounts.manage_validity` 者调整，见 2.2）。

管理员身份带**有效期**（默认 730 天，站点策略可调）：到期后系统自动撤销 `is_staff`（回落普通用户，需重新授予；超级管理员不受限）。

批量动作：

- **封禁**：停用账号（`is_active=False`）、吊销既有会话、发邮件通知。**跳过**自己、超级管理员与已停用账号，动作结束会报告「已封禁 N 个、跳过 M 个」。
- **全站禁言**：需 `messaging.mute_user` 权限（无权限者该动作不显示）。永久禁言（不设结束时间），已禁言或对自己操作会被跳过。禁言只拦写操作，被禁言者仍可登录、阅读、接收通知。

> **不要物理删除用户**：账号注销是**软删除**（[ADR-0027](../adr/0027-account-deletion.md)）——成员在门户自助注销后，邮箱 / 头像 / 身份证明材料 / 登录设备记录被清除、历史内容显示「该用户已注销」，但 `User` / `Profile` 行保留；收到「删号」请求时引导成员走门户自助注销，或对账号停用（停用只挡登录、不清数据）。

### 2.2 资料（`账户 → Profile`）

列表列：用户、真实姓名、身份、已认证（布尔）、已注销（布尔）、注册认证截止。可按「认证状态」（任一认证通道 `approved` 且未过期即「已认证」）、身份（在校生 / 外校生 / 毕业生 / 家长 / 教师）与「注销时间」过滤，按用户名 / 邮箱 / 真实姓名搜索。

有效期字段：**注册认证截止**留空 = 注册日 + 站点「注册后认证宽限」（默认 60 天）；持 `accounts.manage_validity`（默认授予社长 / 信息组）者可对**下位**用户显式延 / 缩（平级 / 上位不可改）；「因超期停用时间」「注销时间」「有效期提示已读标记」为系统维护、只读。认证 / 管理员身份到期前（还剩两个月 / 一个月），系统会自动向本人发站内提醒。

### 2.3 身份审核（`账户 → 身份证明`）

身份证明材料（学生证照片等）为**审计留底**：该后台只读——不能新增、修改、删除；图片经 `/auth/identity-proof/{id}/` 鉴权下载，不经公开 `MEDIA_URL`。整个模块**只对持 `accounts.can_review_identity` 者可见**（无权限者连菜单都看不到）。

列表列：ID、用户、上传时间、人工通道状态、缩略图；可按「人工通道状态」（待认证 / 已通过 / 已驳回）与上传时间过滤。

批量动作（与 `Profile` 页共用，仅持 `accounts.can_review_identity` 者可见）：

| 动作 | 效果 |
|---|---|
| **通过身份审核** | 人工通道置 `approved`，写 `verified_at` / `verified_by`，发邮件告知可使用全部功能。认证通道关闭时拒绝执行并报错 |
| **驳回身份审核** | 人工通道置 `rejected`，发邮件提示可在「账号认证」面板重交材料。驳回 ≠ 停用：账号仍可登录、可重交 |
| **停用账号** | `is_active=False` + 吊销既有会话 + 发邮件通知联系信息组。与认证通道开关无关，通道关闭时仍可执行 |

认证模型要点（[ADR-0006](../adr/0006-verification-model.md)）：「已认证」⇔ 至少一条 `Verification` 通道 `approved`（邮箱 / 人工审批 / 后台委任 / 认证码，任一即可）。通道状态在门户「账号认证」面板自助办理；后台只处理人工审批通道；认证码在「账户 → 认证码」生成 / 吊销（见 2.4）。

### 2.4 认证码（`账户 → 认证码`）

管理员在后台**直接生成**认证码（新增表单自动预生成 12 位、可手改 = 自定义码；有效期必填、初始「当前 +30 天」；可用次数默认 1），线下分发给持码人；成员在门户「账号认证」面板兑换，**即时通过**、无人工环节，通过后认证带有效期（默认 365 天）、到期可用新码重新兑换。生成 / 吊销不受「认证」开关约束（可先备码）；兑换侧受约束。

- **列表列**：认证码、状态（有效 / 已过期 / 已用尽 / 已吊销）、已用次数（`已用/上限`）、有效期至、生成人、备注、生成时间；可按状态 / 生成人 / 生成时间筛选，按码 / 备注 / 生成人搜索。
- **批量动作「吊销认证码」**：软吊销（留底），只停**后续**兑换；**不回溯**已通过者——收回信任走「停用账号」。
- **生成后**：码 / 可用次数 / 生成人不可改；备注与有效期可改（延期场景）。仅「从未使用且未吊销」的码可删除，其余留审计。
- **兑换记录**（`账户 → 认证码兑换记录`）：全局只读，按用户 / 码搜索，作追溯用；码详情页内嵌该码的兑换记录。
- **权限**：标准 CRUD（`accounts.add_authcode` / `view_authcode` / `change_authcode` / `delete_authcode`），默认授予「社长」「信息组」；后台操作需 `is_staff`，不授此权则仅超管可见。

### 2.5 社员身份编号（`账户 → 社员身份编号` / `名册导入批次`）

导入各届社员名册、维护名册行与 8 位识别码（工牌二维码本体，[ADR-0025](../adr/0025-member-identity.md)）。模块整体由命名权限 `accounts.manage_member_roster` 收口（部署迁移默认授予「社长」「信息组」；无权限者连菜单都看不到）。

- **导入名册**（列表页「导入名册」，或直接访问 `…/memberidentity/import/`）：上传 CSV / XLSX → **预检**（逐行给出 新增 / 更新 / 冲突 / 错误 与拟用识别码）→ 确认导入；页面可下载 `.xlsx` 模板。列：姓名 / 班级 / **校牌号** / 入学年份 / 入社时间 / 届数 / 性别 / 电话号码。**只有 姓名 / 入学年份 / 届数 必须填**（认人 + 生成识别码），其余列可以留空，整列缺失也不报错。不收集「年级」「年龄」（每年变动，年级按「入学年份 + 当前学年」推算）与「组别」（社内分组会调整）；**「识别码」列已从模板去掉——一律自动生成**（8 位、全库唯一），旧表里写了也忽略。旧模板多出的列（年级 / 学号 / 年龄 / 识别码 / 组别）不影响导入：年级 / 年龄 / 识别码 / 组别忽略，旧「学号」列按别名读入「校牌号」。重复导入幂等：按「姓名 + 电话」（无电话则「届数 + 姓名」）认行，保留既有识别码与账号绑定，只增量更新；**空白格不覆盖库内已有值**。
- **自动匹配**：导入时按真实姓名唯一命中自动绑定账号；未命中的留待成员注册期**自助认领**（手机号后四位核验）或在此手动绑定（编辑页把「绑定」置空即解绑，绑定元数据自动记录）。**校牌号**（2026-10-23）：在校生 / 毕业生注册时可选填，与名册「校牌号」是同一个值——姓名 + 校牌号与名册唯一命中即在注册时直接绑定（绑定方式「注册时匹配」）；名册为空时按姓名写回，名册有值时以名册为准。用户在「个人中心 → 资料」里的校牌号在后台「资料」列表可直接看到 / 搜索。
- **列表与动作**：可按绑定状态 / 届数 / 状态过滤，按姓名 / 识别码 / 电话 / 用户名搜索。动作：**导出二维码**（勾选行导 ZIP / PNG，工牌用）、**导出条形码**（Code128，内容为 12 位签名载荷 = 6 位唯一键 + 6 位短签名，供站内查询页 `/#/v` 扫码或扫码枪读取；手机系统相机扫一维码只显示数字、不跳转——要「扫了直接出身份」用二维码）、**重新运行自动匹配**（对所选未绑定行）、**解绑账号**（保留名册行）。
- **隐私**：电话仅后台可见、只用于认领校验；公开校验页（`/#/v/<识别码>?s=<签名>`，HMAC 签名防枚举）只显示姓名 / 届数 / 在册状态，**不下发任何联系方式**。
- **导入批次**（`账户 → 名册导入批次`）：每次确认导入留一行审计（文件名 / 操作人 / 时间 / 新增·更新·冲突·错误·自动绑定统计），只读。

### 2.6 安全验证排查（`账户 → 安全问题` / `安全验证记录`）

- **安全问题**（`账户 → 安全问题`）：用户的题库作答记录（题干 + 答案哈希），供信息组排查 / 重置；**答案只存哈希，后台看不到明文**。
- **安全验证记录**（`账户 → 安全验证记录`）：只读审计——谁 / 何时 / 作用域 / 方式（邮箱 / 安全问题）/ 成败 / IP，用于排查「为什么某操作被要求验证」类问题。

### 2.7 账号安全（`账户 → 登录事件` / `账号设备` / `管理端访问记录`）

三张表都是**只读**（不能新增 / 修改 / 删除）：

- **登录事件**：全部账号的登录流水（成功 / 失败 / 被限流 / 待二次验证），可按结果、方式、二次验证、新设备、城市过滤，按用户名 / 邮箱 / IP / 城市 / 设备搜索；账号不存在的撞库也会留一行（`user` 为空）。
- **账号设备**：设备名、平台、最近城市、最近活跃、信任时间、撤销时间。**设备是否已知只由「在该设备完成过一次二次验证」决定**，后台不提供手改信任状态。
- **管理端访问记录**：谁在何时从哪个 IP 查看了登录记录 / 设备列表（`scope` ∈ `login_events` / `devices`）。**查看即留痕**——打开前两张表的列表页就会写一条。

> 登录记录里的位置是 **IP 推算的城市级**结果（可能落到运营商出口城市，IPv6 更差），不是 GPS；本人页面看到的是脱敏 IP。

## 3. 审核（`审核`）

统一审核入口，三张桌子共用 `reviews` app 的模型。三个权限各管一摊：`reviews.moderate`（发布审核）、`reviews.read_feedback`（意见反馈）、`reviews.handle_report`（举报案）。

### 3.1 发布审核（`审核 → 审核`）

`Review` 是新闻 / 活动 / 教程共用的**公开可见性门控**（不改对象自身生命周期）。列表列：ID、状态、新闻、活动、教程、审核人、审核时间、创建时间；可按状态过滤（待审 / 通过 / 驳回 / 下架），按评语与三类标题搜索。

编辑页字段集：状态与评语与审核人 / 审核时间 → 对象（新闻 / 活动 / 教程）→ **预览**（「对象界面」：内嵌同源 iframe 渲染门户页面，另有「新标签打开」链接；该页会隐藏 admin 侧边栏，把内容区让给预览）。

批量动作（仅 `reviews.moderate` 可见）：

| 动作 | 允许的状态转移 |
|---|---|
| **通过** | 待审 / 已下架 → 通过 |
| **驳回** | 仅待审 → 驳回；**评语必填**（后台批量驳回会自动填「后台批量驳回」） |
| **下架** | 仅已通过 → 下架（下架后可再「通过」重新上架） |

非法转移的条目会被跳过并计数（「已通过 N 条。跳过 M 条。」）。审核结果会写站内通知给宿主主人（新闻作者 / 活动发起人 / 教程上传者）。

免审直通：站点策略 `content_review_enabled` 关闭时，新建新闻 / 活动 / 教程直接 `approved`，不进待审队列；持 `reviews.force_publish` 的账号同样免审。关闭开关**不会**批量放行已有待审条目。

### 3.2 意见反馈（`审核 → 意见反馈`）

无对象的投递箱：类别为建议 / 投诉 / 其他，状态「待处理 → 已了结」。列表列：ID、标题、类别、状态、创建人（匿名反馈为空）、了结人、创建时间；按状态 / 类别过滤，按标题 / 详细说明搜索。了结时间等字段只读。

运营约定：匿名反馈不记录提交者；署名反馈才能附媒体（图片 / 视频）作证据，媒体随反馈走统一附件系统（社长对反馈附件「能删不能传」）。反馈没有站内对话，跟进走线下；署名反馈了结后会收到通知。

### 3.3 举报案（`审核 → 举报案`）

有对象的调查票：进行中 → 驳回 / 成立并处置。列表列：ID、状态、新闻、活动、教程、评论、被举报用户、处理人、创建时间；按状态过滤，按处理说明搜索。

处理路径（门户 `/reviews` 或后台查看后处理）：**驳回**须填理由；**成立并处置**会按对象执行默认处置——新闻 / 活动 / 教程下架（已下架则幂等只结案）、评论墓碑删除、用户全站禁言（默认永久）。该动作只要求 `reviews.handle_report`，不要求操作者另持 `reviews.moderate` / `messaging.mute_user`。恢复走既有重新上架 / 解除禁言。

## 4. 新闻（`新闻 → 新闻`）

列表列：标题、作者、头条、已发布、阅读人数、发布时间；可按头条 / 已发布过滤，按标题 / 摘要 / 正文搜索，按发布时间做日期层级导航。正文与封面在编辑页维护（正文为 HTML，服务端会按白名单清洗，`<script>` / 事件处理器 / `javascript:` 一律剥离；iframe 仅放行 https 源并由服务端统一盖戳 sandbox）。

只读字段：阅读人数、发布时间、创建 / 更新时间。标签用水平多选（`filter_horizontal`）。

批量动作 **归档**（需 `news.manage_news`）：把已发布的批量取消发布（`is_published=False`，不再对公众展示），未发布的计入跳过数。

发布前建议核对：标题 / 摘要 / 正文、封面图、标签、头条开关；新发布默认进审核队列（或按站点策略 / 免审权限直通），审核通过后才对公众可见。

## 5. 活动与问卷（`活动` / `活动 → 问卷`）

### 5.1 活动（`活动 → 活动`）

列表列：标题、类型、状态、受众、问卷（链接，调研类型才有）、发起人、截止时间、创建时间；可按类型（众议 / 征集 / 展示 / 调研）、状态、受众过滤，按标题 / 正文搜索，按创建时间做日期层级导航。`questionnaire` 与 `creator` 用自动补全选择。

批量动作 **归档**（需 `activities.manage_activity`）：仅对**征集**生效，把「收件中 / 复审中」置为「已归档」；其他类型计入跳过。注意：带复审的征集走这条会**跳过复审**——它是后台批量归档的显式覆盖，不是「提前关闭」的别名。

状态语义（随类型而异，由 `activities/lifecycle.py` 惰性流转，无定时任务）：

- 众议 / 调研 / 展示：`scheduled`（待开始）→ `open`（进行中）→ `closed`（已结束）；
- 征集：`scheduled` → `collecting`（收件中）→ `reviewing`（复审中）→ `archived`（已归档）；`review_enabled=False` 时跳过复审。

常规运营在门户完成（发起人自管），后台主要用于：改错、代管他人活动（`manage_activity`）、批量归档、查数据。

### 5.2 问卷（`活动 → 问卷`）

一份问卷 = 一个 SurveyJS Schema（JSON）+ 一叠作答。用途两类：`调研`（调研活动 `OneToOne` 指向它）与 `自我介绍`（`kind=join` 单例，招生用，不可删除）。

列表列：ID、用途、标题（取 Schema 的 `title`）、调研活动（链接）、更新时间；按用途过滤，按更新时间做日期层级导航。

**编辑问卷**：进入某问卷的编辑页，对象工具区会出现「编辑问卷」按钮（另可用 URL `.../survey-editor/`）。它打开 SurveyJS Creator 可视化编辑器（中文本地化），右上角「保存问卷」写回 Schema。可保存的窗口：自我介绍问卷始终可改；调研问卷仅「待开始，或已开放且尚无作答」时可改，否则编辑器顶部提示「已有作答或已截止，问卷 Schema 已锁定。」且隐藏保存按钮。

后台可直接「新增」独立问卷（默认用途「调研」）；「自我介绍」为单例，由数据库唯一约束兜底。

**导出统计与作答**（列表页「动作」菜单）：勾选一份或多份问卷后，选「导出统计（CSV / PDF）」或「导出全部作答（CSV / PDF）」直接下载——勾多份时**聚合进同一个文件**（统计 CSV 多一列「问卷」，作答 CSV 按问卷分块）。统计按题型聚合（选择题各选项计数并补零、评分均分与分布、文件题列链接、文本题列全部回答）；作答导出**一行一份**（含作答者与提交时间）。只想导某几份作答时，去「问卷结果」列表勾选后用「导出为 CSV / PDF」（可跨问卷）。

题目标题会变成列名，所以**重名题目自动补父选项前缀**（三个「班级」→「高一 / 班级」「高二 / 班级」；`镜头 / 型号` 而不是全路径）。`panel` 里的题目、以及**选项内子题**（`choices[i].elements`，选中该选项时就地展开的题，如「年级＝高二」下的「班级」、「设备＝相机配件 → 镜头」下的「型号」）都会一并导出——子题答案按自己的 `name` 从作答里取值，未走到的分支留空。`paneldynamic`（可增行矩阵）暂不摊平：它的作答是「每行一个 dict」的列表，摊成普通列会永远为空。布尔题按中文「是 / 否」导出（不是 `True` / `False`）。

### 5.3 问卷结果（`活动 → 问卷结果`）

列表列：问卷、作答者、设备标识、提交时间、「查看作答」链接、「统计」链接；按问卷用途过滤，按问卷 Schema / 用户名 / 设备标识搜索，按提交时间做日期层级导航。作答、提交时间、设备标识为只读。

- **查看作答**：以只读问卷形式展示一份作答（SurveyJS display 模式），页头标注作答者（登录用户名，或「访客 · <设备标识前 8 位>」）与提交时间。
- **统计**：SurveyJS Analytics 可视化面板（图表）+ 作答列表；也可从问卷编辑页的「统计」进入。
- **导出所选作答**：勾选若干行后用「动作」菜单的「导出为 CSV / PDF」——可跨问卷，多份时按问卷分块聚合成一个文件（列同「导出全部作答」：用户、提交时间 + 各题标题）。

作答次数规则：**加入（自我介绍）问卷同一人最多 5 次**（登录按用户、访客按设备标识计数）；调研问卷仍限 1 次。设备标识即浏览器 localStorage 的 UUID——清存储或换浏览器可再交，这是 Web 侧上限。

### 5.4 投票与作品（众议 / 征集）

- **投票选项**（`活动 → 投票选项`）：选项文本、所属活动、排序；按活动类型过滤，活动用自动补全。开放投票后即锁定，不增删改。
- **选票**（`活动 → 选票` / `活动 → 选票选项`）：记录谁投了哪些选项。秘密投票下仅超级管理员可见个人明细，常规请只看聚合计数。
- **作品**（`活动 → 作品`）：征集投稿。列表列：活动、提交者、复审状态（待复审 / 录用 / 退稿）、复审时间、创建时间；按复审状态与活动类型过滤，按活动标题 / 提交者 / 复审评语搜索。复审本身在门户的征集复审界面做，后台用于查数、补评语、代管。

## 6. 任务（`任务管理`）

- **任务**（`任务管理 → 任务`）：列表列标题、状态、优先级、创建人、负责人、创建时间；按状态 / 优先级过滤，按标题 / 描述搜索。编辑页的标签与协作者为水平多选，创建 / 完成时间为只读。
  批量动作 **归档**：对非终态任务执行取消（`cancelled`）；已完成 / 已取消计入跳过。
  状态语义：待处理 → 进行中 → 待验收 → 已完成；另有「审核中」（有待审认领申请）与已取消。负责人↔状态联动由 `status_for_assignee` 统一处理（有负责人即进行中）。
- **认领请求**（`任务管理 → 认领请求`）：列表列任务、申请者、状态（待审核 / 已通过 / 已拒绝）、审核人、创建时间；按状态过滤。审批在门户任务详情页完成，后台用于查数。
- **标签**（`任务管理 → 标签`）：名称 + 颜色（`#RRGGBB`）。标签被新闻、任务共用，删除前确认无引用。

## 7. 教程（`教程集锦 → 教程`）

列表列：标题、文件类型（视频 / 文档）、上传者、播放量、创建时间；按文件类型过滤，按标题 / 文件名搜索，上传者用自动补全。教程入库即生效（审核只门控公开展示，不改生命周期），视频不转码、原文件播放。公开可见性由统一审核轴控制，在「审核 → 审核」里通过 / 驳回 / 下架。

## 8. 招生（`加入社团 → 招生公告`）

单例，无需新增（新增按钮被禁用），也不可删除。编辑正文（HTML）即更新「加入社团」落地页上的本年度公告；报名者须勾选「已知晓」后才能进入自我介绍问卷。问卷本体在「活动 → 问卷」里编辑（用途 = 自我介绍），报名结果在「招生」相关的问卷结果列表查看。

## 9. 考试看板（`考试看板`）

- **考试**（`考试看板 → 考试`）：标题 + 内嵌「考试批次」行内表单。新建一场考试时直接在下方添加批次。
- **考试批次**（`考试看板 → 考试批次`）：批次名称、所属考试、排序，内嵌「科目场次」行内表单。同一批次内科目场次不得重叠（结束 = 下一场开始允许），间隙即休息。
- **科目场次**：科目、考试日期、开始 / 结束时间、排序。日期与时刻按 **Asia/Shanghai 墙钟**解读（全局 `TIME_ZONE` 仍是 UTC）。
- **题目误刊**（`考试看板 → 题目误刊`）：说明（≤500 字）、图片、所属考试、到期时间（默认跟该考试当前场次结束）、撤回时间。发布后经公开 WebSocket 广播到所有打开的教室看板；可同时多条，按发布顺序在考试结束时依次失效。

读写：课表与误刊的读取匿名开放；写入需 `exam_board.manage_exams`（信息组默认持有）。

## 10. 关于页（`关于页`）

- **关于页**（`关于页 → 关于页`）：单例，不可新增 / 删除。维护标题、正文、成立时间、指导（默认「信息组」）、简介等门户静态行。
- **关于区块**（`关于页 → 关于区块`）：五个固定键的独立区块——`club`（关于社团）、`school`（关于一中）、`site`（关于网站）、`contact`（联系我们）、`campus-overview`（校园一览）。每块可编辑标题、正文（HTML）、排序、校园全景图外链（`panorama_url`）与文档附件。文档按原件嵌入展示（PDF 用 iframe、`.docx` 前端渲染），始终可下载；上传覆盖该区块附件。

权限：所有区块与静态行共用 `about.manage_aboutpage`，**不按块拆权限**。

> `panorama_url` 是**待退役的历史字段**：全景图已改为站内图库（见 15），「校园一览」的按钮以后指向站内全景浏览页；过渡期两者均可保留。

## 11. 站内通信（`站内通信`）

- **横幅公告**（`站内通信 → 横幅公告`）：正文、链接（可空）、开始 / 结束时间、优先级（数值越大越优先，并列取较新）。**同时只展示一条**：未过期中优先级最高者胜出。访客无 WebSocket，门户靠轮询 `GET /messaging/banners/current/` 获取。写入需 `messaging.manage_announcement`（信息组默认持有）。
- **禁言**（`站内通信 → 禁言`）：被禁言用户、操作人、理由、开始 / 结束时间、解除时间。当前生效 = 最新一行未解除且未到期。列表可按时间过滤、按用户名 / 理由搜索。发禁言走门户或用户页批量动作，后台用于查记录与核对到期。
- **评论区**（`站内通信 → 评论区` / `评论区评论`）：宿主为新闻 / 活动 / 任务。状态：开放 / 禁言（已有评论可见，不能新发）/ 关闭（普通读者不可见，协管仍可管）。拧状态与墓碑删除需宿主主人或 `messaging.manage_comment_thread`。评论列表可按撤回 / 删除时间过滤、按内容搜索。
- **会话与私信**（`站内通信 → 会话` / `私信` / `消息已读状态`）：1:1 私信。会话编辑页内嵌消息行内表单（只读）。**后台不做内容治理**——请通过举报案走「成立并处置」，或对账号禁言。
- **通知**（`站内通信 → 通知`）：只读（禁止增 / 改 / 删）。列表列接收人、类别（审核 / 活动 / 评论 / 私信 / 广播 / 身份有效期 / 纪律）、事件、已读时间、创建时间；按类别 / 已读过滤。用于排查「某人说没收到通知」类问题。

## 12. 全站弹窗公告（`全站弹窗公告`）

一条公告 = 一次「全站弹窗 + 站内通知 +（可选）邮件」的发布（[ADR-0042](../adr/0042-site-wide-popup-announcement.md)）。模块整体由命名工作流权限 `announcements.manage_announcements` 收口（迁移默认授予「社长」「信息组」；无权限者连菜单都看不到）。前台只读，发布 / 编辑 / 下线 / 已读都在后台。

- **编辑表单**：标题 + 正文（纯文本摘要，可留空）；**文档原件可选**（PDF / .docx，≤20MB）——只保存原件、**不转站内富文本**，浏览端用 pdf.js / docx-preview 按原排版渲染并附「下载原件」。正文与文档至少要有一个。
- **发布范围**：全站（含未登录访客）/ 注册用户 / 认证用户 / 管理员。勾「同时发送邮件」时只发到**已认证**邮箱（未认证地址不发，避免误发），走通知投递队列、可重试。
- **发布 = 保存即推送**：状态设为「已发布」且从未发布过 → 立刻向受众写站内通知（可选邮件），发布时间自动写入；已发布过的公告再保存**不会重复推送**。设置下线时间后，到点不再弹出，但站内通知里仍可回看（`/#/announcements/<id>`）。
- **批量动作**：「发布所选公告」「下线所选公告」。
- **统计**：表单底部统计栏显示受众数 / 已读人数 / 阅读率 / 邮件入队与送达数，并链接到**已读明细页**（逐人列出已读时间或「未读」）。已读口径 = 登录用户（关闭弹窗即写台账，一人一行、跨设备只算一次）；匿名访客用 localStorage 记住「已看过」，不计入阅读量。
- 列表可按状态（草稿 / 已发布 / 已下线）、受众、是否发邮件过滤，按标题 / 正文搜索；按创建时间分层。

## 13. 附件（`统一附件`）

`统一附件 → 附件`：列表列 ID、文件名、文件类型（图片 / 视频 / 文档 / 压缩包 / 其他）、上传者、任务 / 意见反馈 / 新闻、上传时间；按类型过滤、按文件名搜索。上传时间、大小、类型为只读。附件必须且只能挂在一个父级（任务 / 意见反馈 / 新闻 / 作品 / 展品）上；删除父级或附件行会同步回收磁盘文件（`post_delete` 信号，无需定时任务）。

反馈附件的配额与规则见 [附件与上传 API](../api/attachments.md)；身份证明材料不在这里，走 `private_media/` 与「身份证明」模块。

## 14. 站点策略（`通用 → 站点策略`）

单例（pk 恒为 1），列表页会直接跳转到表单；不可新增（已有行时）也不可删除。改动**即时生效**（保存即失效缓存），无需重启。分七个字段集：

| 字段集 | 关键字段 |
|---|---|
| 认证 | 认证通道开启（关闭后不可新开或完成任何通道；已通过者仍算已认证）、认证有效期（天）、管理员身份有效期（天）、注册后认证宽限（天） |
| 审核 | 开启内容审核（关闭后新建新闻 / 活动 / 教程直接通过；已有待审不批量通过） |
| 评论 | 启用评论区、评论最大嵌套深度（1 = 仅根评论） |
| 私信 | 启用私信（关闭后前端不再显示入口，发信 403） |
| 注册与限流 | 开放自助注册、开放社员身份自助认领；每 IP 每日注册、每 IP 每小时重发认证邮件、每 IP 每小时登录失败、每用户名每小时登录失败、每 IP 每日匿名反馈、每用户每日举报、每账号每小时认证码兑换失败、社员认领失败（按账号 / 按 IP）、扫码校验（按 IP）、安全验证码（按账号 / 按 IP）等各项额度 |
| 上传 | 同步上传单文件上限（默认 50MB）、tus 图 / 视频上限（默认 500MB） |
| 自动更新 | 开启自动更新、轮询间隔、更新时区、窗口开始 / 结束时刻、窗口结束前截止分钟、保留发行包份数、保留数据库快照份数 |

自动更新的窗口与轮询等旋钮在此调整；`UPDATE_GITHUB_TOKEN` 等密钥仍在 `.env`（改完需重启，见[部署指南](deployment.md)）。全站维护拦截不在本页——它是文件旗标 `run/MAINTENANCE`，由 `manage.py maintenance on|off|status` 或更新守护进程控制。

> 「同步上传单文件上限」同时是**全景图导入的上限**（全景图走同步通路，见 15）；改小它可能让已上线的全景导入上限也跟着变小。

## 15. 校园全景图（`校园全景图`）

- **校园全景图**（`校园全景图 → 校园全景图`）：**不能新增**（后台表单不跑切片流水线，直接建行只会留下没有层级图的坏记录），可查看全部字段并微调标题 / 描述 / 排序 / 公开与**初始视角**（`initial_yaw` / `initial_pitch` / `initial_fov`）。
- 列表列：排序、标题、切片状态（切片中 / 可浏览 / 切片失败）、来源（手动上传 / DJI 全景图导入 / 静态素材导入）、设备型号、宽高、公开、更新时间；可按切片状态 / 来源 / 公开过滤，按标题 / 描述 / 原文件名 / 设备型号搜索。
- 只读字段：原图与尺寸、投影、来源、设备型号、元数据（GPano / drone-dji 快照）、拍摄朝向、瓦片目录与层级、预览 / 缩略图路径、切片状态与失败原因、创建人与时间。
- **失败原因非空即切片失败**：在门户的全景图管理入口点「重新切片」（或调 `reprocess` 接口）；**不需要重新上传原图**。

**上传入口在门户**（不在后台）：持 `panorama.manage_panoramas` 的成员在门户全景图管理页上传——支持 DJI Fly / DJI GO 4 合成的 2:1 球面全景 JPEG，也支持装着全景图的 zip（服务端解包挑图后**丢弃压缩包**）。导入时自动读 XMP 适配初始视角，并切出多级层级图 + 低清预览；浏览侧只吃层级图，所以首屏远小于原图。

**既有静态素材**：`uv run python manage.py import_static_panoramas [--dry-run] [--force]` 把 `static/panorama/pano_*.jpg` 导进图库并重切片（幂等）。既有记录需重建时优先用「重新切片」（保留记录 ID 与手工调整）；`--force` 为删旧建新，ID 会变号、手工调整会丢。旧的静态全景页保留作兜底，待新全景浏览页上线验证后再下线。

权限：`panorama.manage_panoramas`（增 / 删 / 改 / 重切）；读取不需权限（公开侧只出「已公开且可浏览」的条目）。详见 [全景图 API](../api/panorama.md) 与 [ADR-0022](../adr/0022-campus-panorama-library.md)。

## 16. 日常运营建议

- **每天**：看「审核 → 审核」待审队列、「审核 → 举报案」进行中案件、「审核 → 意见反馈」待处理；抽查横幅公告是否过期未撤。
- **每周**：复核后台账号与「社长 / 信息组」成员（换届、离职及时回收）；清理过期横幅；检查教程 / 新闻是否有失效链接或不合规内容；核对考试看板课表与误刊状态。
- **每月**：与运维一起核对 `.env` 与站点策略；盘点附件与媒体占用（全景层级图会明显增加 `media/` 体积，删记录时已自动回收）；演练一次「驳回 / 下架 / 恢复」全流程。
