# 社员身份编号：名册导入、自动匹配、自助认领与扫码校验

日期：2026-10-18

> **修订（2026-10-30）**：工牌上不一定印得出二维码，所以新增**编号查询入口** `/#/v`（手机摄像头扫条码 / 手动输入）。为此把条形码载荷从「裸 8 位识别码」改成 **12 位签名载荷**（`6 位唯一键 + 6 位十进制短签名`），见文末「查询入口（2026-10-30 增补）」。原「条形码 = 裸码」的结论已被该节覆盖；手输查询的身份分档额度体系保持不变。

每一届社员名册（CSV/XLSX）原游离于系统之外，工牌无从核验。本 ADR 在 accounts 内建立「社员身份」档案：**管理员导入名册 → 自动按真实姓名匹配账号 → 注册期自助认领（手机号后四位）→ 每人生成唯一识别码 → 批量导出可扫码校验的二维码**。名册模块整体由命名工作流权限 `manage_member_roster` 收口（沿用 [ADR-0020](0020-authcode-verification-channel.md) 的命名权限思路）；注册改为「注册即登录」（原为注册后手动登录），以支撑认领阶段。扫码校验页会让真实姓名定点可见，是对 [ADR-0006](0006-verification-model.md) 决策 3 的受控突破。

## 决策

1. **识别码规则**（集中 `accounts/member_codes.py` 一处）：`[入学年份后2位][首次入社届数2位][姓名排序序号2位][校验码2位]`——如 2026 入学 · 第 2 届 · 当次名单姓名首字母序第 5 位 = `26020542`。
   - **序号**：按**当次导入名单**的**姓名拼音首字母**分配（`accounts/name_order.py`，零依赖：GB2312 一级字 3755 个本身按拼音排序，用 23 个字母段的起始字反推首字母；多音字姓氏按**姓氏读音**改判，如 单 shàn→S、解 xiè→X、查 zhā→Z、仇 qiú→Q、区 ōu→O、乐 yuè→Y、尉 yù→Y；二级字区姓氏走显式覆盖表 覃 缪 隗 佘 冼 邝……），同首字母内按 GBK 序细排，01 起、单届上限 99。
   - **一次导入可混多届**：按（入学年份, 届数）分组、各组独立从 01 编号（组间靠前缀区分，互不干扰）。
   - **补录接续**：同组新行从「已有最大序号 + 1」起，组内仍按首字母排序后依次占用，**不重排已发码**——先发的工牌码不会因补录跳号。重复导入按身份键认行、保留原码。
   - **校验码**：ISO 7064 MOD 97-10（`check = 98 − (前6位 × 100 mod 97)`；完整 8 位数 `mod 97 ≡ 1`）——手输 / 抄录错误的单字符篡改可被自检发现（测试逐位验证漏检 0）。
   - **编码一律由系统自动生成**——表格中的「识别码」列仅作参照、导入时忽略（2026-10-18 修订）。**2026-10-19 规则修订**：旧规则 `[…][届内序号4位]`（首空位分配）改为上式——4 位流水对 8 位空间浪费且无自校验；上线时生产名册 0 行，无数据迁移。
2. **数据模型**：`MemberIdentity`（名册一行：`code` 唯一、`user` 非空唯一 = 绑定、`phone` 仅供认领校验、状态 `active/graduated/left`）；`IdentityImportBatch`（导入批次审计；**不物理删除**名册行，重复导入走幂等更新）。
3. **导入管线（两步式）**：后台「社员身份 → 导入名册」子页面；上传即**预检**（不落库，逐行给出 新增/更新/冲突/错误 与预览码），确认后入库并记批次。CSV（utf-8-sig / gbk 自动探测）与 XLSX（openpyxl）；按**表头名**识别列、顺序无关、多余列忽略；班级/校牌号等按字符串读（保前导零）、公式取计算值。模板下载由后台现场生成。**列清单（2026-10-23 修订，二次修订去掉「组别」）**：`姓名 / 班级 / 校牌号 / 入学年份 / 入社时间 / 届数 / 性别 / 电话号码`——只收不随时间变的档案信息：不含「年级」「年龄」（每年变动，年级按「入学年份 + 当前学年」推算）、不含「识别码」（一律系统生成）、不含「组别」（社内分组会调整，也不是认人 / 编号所需）；「校牌号」取代旧「学号」（同一栏位改名，旧表头「学号」按别名读入）。**除 姓名 / 入学年份 / 届数（认人 + 生成识别码所必需）外，其余列都可留空**；旧模板多出的列（年级 / 学号 / 年龄 / 识别码 / 组别）按未知列忽略、照常导入。
4. **幂等重复导入**：认行键 = 姓名＋电话号码（无电话时届数＋姓名；表格「识别码」列不参与认行）；命中**更新**动态字段并**保留**识别码与既有绑定——**空白格 = 「该项没填」，不覆盖库内已有值**（2026-10-23 修订：所有非必需列都允许留空，避免半张表把既有班级 / 校牌号 / 电话洗掉）；冲突（多义命中）与错误行不入库、报告单列。
5. **自动匹配**：导入后对未绑定行按「姓名归一化全等（去空白、西式大小写折叠，`member_roster.normalize_name` 单一实现）＋ 候选账号唯一」自动绑定（`bind_method=auto`）；歧义不动作，管理员可重跑或手动绑定 / 解绑（`bind_method=admin`）。
6. **自助认领**：注册后的认领阶段（「以下身份是否是你？」）与个人页「社员身份」面板共用同一路径；候选 = 未绑定且姓名与账号 `real_name` 归一后一致的行；校验**手机号后四位**（服务端强制姓名一致，不信任前端候选列表）；可跳过；开关 `member_claim_enabled`（默认开）；失败按账号（5 次/时）＋ IP（20 次/天）双通道节流、**只计失败**。
7. **二维码与公开校验**：二维码内容 = `{FRONTEND_URL}/#/v/{码}?s={签名}`；**签名 = HMAC-SHA256(密钥, 识别码) 截断 16 位 hex**，密钥默认由 `SECRET_KEY` 派生、`MEMBER_QR_SECRET` 可覆盖——识别码是结构化数字，签名把「猜号遍历」一律挡成 404。校验端点 `GET /auth/member/check/` 公开、按 IP 限流（60 次/时），命中仅返回 姓名 / 届数 / 状态 / 头像——**电话、校牌号、邮箱绝不外显**。批量导出 = 后台列表动作，ZIP 内含 `识别码_姓名.png`（512px，segno 渲染）。
8. **权限与开关**：命名权限 `accounts.manage_member_roster` 默认授予「社长 / 信息组」（迁移 0016，同 0012 模式）；认领开关与认领 / 校验限流参数入站点策略（后台可调）。
9. **校牌号（2026-10-23 增补）**：`MemberIdentity.card_no` 是名册里的校牌号；注册页对**在校生 / 毕业生**提供**选填**的「校牌号」，写入 `Profile.card_no`——**两者是同一个值**，不是两套数据：
   - 注册时「姓名 + 校牌号」与名册**唯一**命中未绑定行 → 直接绑定（`bind_method=register`），免手机号后四位（校牌号印在校牌上，属半公开信息，所以必须姓名与校牌号同时对上）；
   - 没命中（名册未导入 / 校牌号不一致 / 同名多行）**不报错**：先存 `Profile.card_no`，名册导入或后台「重新运行自动匹配」时由 `sync_card_numbers()` 按姓名写回名册行；
   - 已绑定行两边对齐：**名册有值时以名册为准**（学校档案），名册为空时用资料补；
   - 校牌号**不对外公开**：公开校验页与认领候选都不下发，只有本人 `/auth/member/` 的 `bound` 可见。

## 被否的方案

- **识别码后 4 位用随机数或电话派生**：随机不可读；电话涉隐私且老数据不规整。改用届内序号（可读、稳定、可人工核对）。
- **认领要求更高证据（学号 / 全手机号）**：学号不总在册；全手机号等于问隐私。姓名一致 + 后四位 + 双通道限流为「可接受」档位，管理员可随时改绑 / 解绑。
- **导入直接落库（无预检）**：名册来自人工整理、错误率高；预检让冲突与错误在落库前可见。
- **校验页用服务端会话态签名**：引入状态与过期管理成本，无必要；无状态 HMAC 已足够。

## 工牌产物（2026-10-19 增补）

- **二维码**（既有）：内容 = 带签名的校验 URL（`/#/v/<码>?s=<签名>`），扫码即查、防枚举；512px PNG。
- **Code128 条形码**（本次；定位 = **扫码枪 / 手工输入到后台检索**）：内容 = **裸 8 位识别码**；**不是链接载体**——2026-10-19 微信实测：扫 Code128 只显示数字、不跳转；把校验链接编进条码（596 模块 / 约 104 mm 宽）后微信无法识别。「扫码打开校验页」一律用二维码签名 URL。8 位数字自动走 Code128C（4 个字符对 + 校验位，79 模块）；后台 action「导出条形码（扫码枪读取识别码 · ZIP / PNG）」，文件名同二维码导出（`识别码_姓名.png`）。
- 实现：`accounts/member_barcode.py`——编码用 reportlab Code128（站内已有依赖），渲染用 Pillow（reportlab 的 renderPM 需要 rlPyCairo 后端，不为单一导出引入新依赖）。参数：module 4px / 条高 60px / 两侧静区 10 模块 / 下方印识别码。
- **矢量导出（2026-10-30 增补）**：后台 action「导出条形码 SVG（矢量 · 透明底 · ZIP）」出 `识别码_姓名.svg`。几何与 PNG 同构——1 用户单位 = 1 模块，`viewBox="0 0 121 22"`；`width` / `height` 按 400dpi（module 4px ≙ 0.254mm）折成毫米，121×4px = 30.734mm，放进印刷版面尺寸即实物尺寸、随意放大不糊。**背景不画任何底色矩形**：条与字之间的空隙就是画布本身，叠在工牌底色上露出来的是承印物，而不是一块白板；确实要白底时由版面自己垫一层。人眼可读行是 `<text>` + `text-anchor="middle"`（缺字体时按 `font-family` 回退，居中不会跑位），`show_text=False` 可只出条。
- 验证：本地 zxing-cpp 解码实测（`26020001` / `26020002` / `26029999` / `ABC123` 全部读回原文）+ 微信侧实测（一维码只出数字、链接版扫不出，见上）；CI 断言三层——符号序列与校验位公式独立复算、79 模块结构、PNG 像素条空宽度与编码器输出逐段一致；SVG 侧同样四层断言——XML 良构、无铺满画布的矩形（即透明底）、rect 的 x/width 还原成条空游程 = 编码器输出、去掉文字层后高度只剩 15 模块。

## 兼容与迁移

- **注册行为变化**：注册成功即建登录会话（原「注册后去登录」）；会话记录由既有 `user_logged_in` 信号统一落 `UserSession`；与 10 分钟登录保护无交互（属首次登录）。
- **新依赖**：openpyxl（MIT）、segno（BSD，纯 Python）。新增模型两张（accounts 0015 / 0016）、站点策略五项（common 0010）。
- **隐私边界**：校验页展示姓名 / 届数 / 状态（头像可选）；`phone` 仅后台与认领校验使用、绝不下发。
- 相关文档：[API · accounts](../api/accounts.md)。

## 查询入口（2026-10-30 增补）

**起因**：工牌上不一定印得出二维码（版面 / 打印条件），需要「只有条码也能查」的兜底；手机摄像头扫码需要站内落地页，手动输入也需要入口——三者合成 `/#/v`。

**决策：条形码载荷改为 12 位签名载荷**，`6 位唯一键 + 6 位十进制短签名`：

- **为什么只带前 6 位**：`[入学年份2][届数2][序号2]` 本身唯一；末 2 位是 ISO 7064 校验位、专供手抄自检，条码由机器读（Code128 自带模 103 校验符），服务端反查后重算即可。
- **为什么签名必须纯数字**：Code128C 每 2 位数字占 11 模块（起始/校验/终止另占 35）；混入字母就掉回 Code128B（每字符 11 模块），宽度翻倍且抗模糊骤降。实测：8 位 + 16 位 hex = **255 模块**（≈84mm），模糊半径 1.6px 解码 15/24、2.2px 0/24；同条件纯数字版 24/24。12 位数字 = **101 模块**（0.254mm/模块含静区 30.7mm，比原 8 位裸码的 32.7mm 更短）。
- **为什么 6 位签名够**：10⁶ 空间；攻击者要同时命中结构合法的键与签名，配合端点级 IP 频控（300/时）命中率可忽略。
- **域分离**：`HMAC-SHA256(密钥, "barcode:" + 完整 8 位码) → 前 8 字节 mod 10⁶`；与二维码的 16 位 hex 签名互不通用。

**与额度体系的关系（关键）**：12 位载荷带签名 → **不消耗** 24 小时额度（现场连扫几十上百张工牌，按额度三步就卡住）；8 位裸码 / 真实姓名仍走身份分档额度，口径不变。两条路的防枚举依据不同：前者靠签名 + IP 频控，后者靠额度。

**扫码实现**：浏览器原生 `BarcodeDetector` 在 iOS Safari 全版本默认关闭（caniuse），故引入 `barcode-detector`（MIT，polyfill，底层 `zxing-wasm`）。该包 wasm 默认从 jsdelivr CDN 取、国内不可用——改为 webpack `asset/resource` 打包、`locateFile` 指回自托管副本（925KB，仅点「扫码」时加载）。

**验证边界（诚实记录）**：本地用 Playwright 假摄像头喂条码视频，走通「wasm 解码 → 12 位载荷 → `/member/lookup/` → 社员信息」全链；**iOS / 微信内置浏览器的真机 `getUserMedia` 未实测**。0.254mm 模块的打印可扫性需实物验证，未过则退 0.30mm。
