# 公开受众投票：游客可投 + 设备标识判重

日期：2026-09-24

众议 / 展示的投票原先一律要求「登录 + 已验证」。社团希望部分投票（如面向全校的作品评选）对未登录访客开放：分享链接、任何人可投，同时防重复投票。调研的「公开受众 + 访客按设备标识一份」模式（[ADR-0014](0014-questionnaire-independent.md)）已有先例，本次把受众维度扩展到投票。

## 决策

1. **复用 `Activity.audience`**（原调研专用）作为投票资格开关：`public` 时任何人可投（含未登录游客）；`members`（默认）保持登录 + 已验证。众议 / 展示创建时可选受众，创建后不可改（与调研同规则）。不新造 `public_voting` 字段。
2. **游客按设备标识判重**（复用 ADR-0014 的 `X-Device-Id`）：游客投票必须带合法 UUID，按 (活动, 设备标识) 一设备一张，DB 条件唯一约束（`unique_ballot_per_device`）兜底并发窗口；登录用户仍按账号一人一张。
3. **游客票记录 IP 与设备标识**：`Ballot.voter` 改为可空，新增 `voter_ip` 与 `device_id`。IP 取 `X-Forwarded-For` **末段**（Nginx `$proxy_add_x_forwarded_for` 将真实来源追加在末尾，最左可被客户端伪造）；**只留痕、不判重**——学校 / 移动网络出口 NAT 共享 IP，按 IP 判重会误伤。
4. **公开受众活动对访客可见**：访客的列表 / 详情范围从「公开调研」扩展到「公开受众的调研 + 众议 + 展示」，否则游客无从看到入口、无法投票（审核轴不变，仍只出过审项）。
5. **提前结算只数已验证成员的票**：公开受众引入游客票与未验证用户票后，「全员投完」（分子 ≥ 已验证成员数）的分子收窄为**已验证成员的票**，否则非成员票会虚增票数提前关闭投票。

## 被否的方案

- **新造 `public_voting` 布尔字段**：与 `audience`（参与资格）语义重复，调研已有先例；两套开关徒增同步负担。否。
- **游客按 IP 判重**：NAT 场景误伤（全校 / 整个运营商出口共享一个 IP）；且 `X-Forwarded-For` 最左可伪造。IP 仅留痕。否。
- **游客票不落库、仅计数**：无法判重、无法审计，也无法向游客回显「你投过」。否。
- **未验证登录用户视同游客（按设备判重）**：登录态已有账号身份，按账号判重更稳（换设备无法重复）；与调研作答的既有规则一致。否。

## 后果

- 迁移：`Ballot.voter` 可空 + `voter_ip` / `device_id` + 条件唯一约束；既有数据不受影响（旧票 voter 非空）。
- 投票端点认证从「已验证」改为按受众分派（`public` → `AllowAny`；`members` → 登录 + 已验证，401 / 403）。
- 访客可见范围扩大（仅 `audience=public` 的众议 / 展示；审核轴与成员全量可见规则不变）。
- 前端：创建表单受众选择扩展到众议 / 展示；投票明细中游客票显示「游客」；详情页公开活动带「公开」徽章。
- 防刷边界（已知且接受）：账号票与设备票不互查——同一人「登录投一票 + 退出后以游客再投一票」无法被单侧判重捕获；与调研作答的既有边界一致。

## 2026-10-31 修订（安全审计 H-2）

**问题**：设备标识由客户端生成（localStorage UUID），判重只能挡住「同设备重复提交」，挡不住脚本每次换一个 UUID 的批量刷票；且原设计没有任何服务端限流。公开受众投票若用于作品评选，结果完整性可被单个攻击者操纵。

**修订**（不改变「游客可投」的产品语义）：

1. **按（IP + 活动）限流**：未登录请求每小时最多 `SiteSettings.public_vote_per_ip_per_hour` 票（默认 120），超出返回 429。按活动分桶，避免一场评选耗尽同一出口 IP 在另一场的额度；登录用户按账号判重，不占此额度。
2. **可选 Turnstile**：站点启用 Turnstile（`TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET_KEY` 均非空）时，游客每投一票须带有效的 `turnstile_token`；成员投票不需要。未启用时行为不变。
3. **剩余风险（明确保留）**：设备号仍可轮换，分布式 IP 的慢速刷票无法在「匿名 + 无账号」前提下根除。若某次投票的结果具有约束力（评奖、公投），应把该活动设为 `audience=members`（登录 + 已认证一人一票），或把游客票仅作人气展示。本轮不改变既有活动的受众设置与计票口径。
