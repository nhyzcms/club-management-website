# 功能总览

本页回答「系统能做什么」，按业务域列出**全部**能力与规则落点。三条配套线索：

- **术语**：任务、活动、众议、征集、展示、调研、作品……见 [CONTEXT.md](https://github.com/nhyzcms/club-management-website/blob/main/CONTEXT.md)
- **设计取舍**：每条能力背后的「为什么」见 [ADR](adr/)
- **接口细节**：字段、权限、错误码见 [API 参考](api/README.md)

## 1. 账号与安全

### 登录与注册

- 邮箱认证、人工审核、认证码、预约（教师）等多条认证通道；**任一条通过后，其余通道自动显示「无需再次认证」**，不重复折腾。
- **注册查重**：用户名、邮箱各自唯一；真实姓名不单独判重，**姓名 + 校牌号**同时一致才视为同一账号，提示「请登录原账户」。
- 教师注册可选填部门（德育处 / 体育组），存枚举 key 防脏值；审核队列显示「教师 · 德育处」。
- **记住登录**：勾选 → 30 天持久会话；不勾 → 关闭浏览器即失效（桌面默认不勾，移动端默认勾选）。

### 忘记密码（双通道）

邮箱链接自助重置，或向管理员申请手动重置：上传**学生证 / 校牌**照片作证明（**不要提交身份证照片**）→ 审核台「密码重置」桌批准 → 密码重置为 `123456`、所有设备下线、首次登录**强制改密**。

### 多端登录（[ADR-0028](adr/0028-multi-device-login.md)）

同一账号最多 **3 台设备**同时在线（网页 / 手机浏览器 / App 各一台，按 UA 归类），第 4 台登录自动顶掉**最久未活动**的那台。个人中心「登录设备」可查看在线设备、下线单台或「下线其他所有设备」；退出登录只下线本机。

### 陌生设备二次验证（[ADR-0026](adr/0026-stepup-verification.md) / [ADR-0043](adr/0043-stepup-factor-registry.md)）

- 设备信任**只由「在这台设备上完成过一次二次验证」写入**，不靠 UA 猜。
- 可用因子：滚动密钥（TOTP，RFC 6238，最多 5 个）、邮箱验证码、安全问题、恢复代码（10 个一次性码）。
- 一个因子都没绑定时，本次豁免放行并引导绑定，设备保持陌生。
- 应急开关：生产可置 `LOGIN_CHALLENGE=0` 关闭挑战。

### 账号与安全中心（[ADR-0029](adr/0029-account-security-center.md)）

`/#/security` 把改密 / 安全问题 / 登录方式 / 设备 / 登录记录收进一处。登录记录带城市级 IP 定位与地图打点（无地图 key 时降级为文字），IP 在本人界面脱敏。管理端新增登录事件 / 账号设备 / 管理端访问记录三张**只读**表，查看即留痕。

### 有效期与注销

- **账号有效期**（[ADR-0041](adr/0041-account-validity.md)）：注册成功 / 认证通过时弹窗说明到期时间与剩余天数（已读标记存服务端，续期后才再弹）；认证面板常显到期时间。兜底命令 `manage.py enforce_validity`。
- **账号注销**（[ADR-0027](adr/0027-account-deletion.md)）：**软删除**。`Profile.deleted_at` 标记，只清邮箱 / 头像 / 身份证明材料 / 登录设备记录；`User`、`Profile`、`MemberIdentity`（社员编号）行永不删除；历史私信与评论显示「该用户已注销」。提交后再弹一次二次确认才执行。
- **管理员强制彻底删除**（物理删除，不可恢复）：后台「用户」列表动作，物理删除 `User` 行；**保留内容并匿名化（默认）**或**连内容一起删**二选一，每次写 `AccountDeletionLog` 审计。不能删自己 / 最后一个可用超管；删管理员需超管。服务器侧应急入口 `manage.py hard_delete_account`。详见[管理后台指南](operations/admin-guide.md)。

### 访问控制（[ADR-0005](adr/0005-access-control-principle.md)）

四个正交轴：身份徽章（展示用）、角色能力（`has_perm`，**唯一的访问控制依据**）、组成员身份（纯展示文本）、对象所有权（逐行组合）。前端只吃语义化 `can_*` 能力布尔，不吃原始权限代号。详见 [访问控制指南](guides/access-control.md)。

## 2. 社员身份（[ADR-0025](adr/0025-member-identity.md)）

名册导入 → 按真实姓名自动匹配账号 → 注册后自助认领（手机号后四位）→ 每人生成唯一**识别码** → 工牌二维码 / 条形码导出与公开校验页。

- 识别码 = `[入学年2位][首次入社届数2位][姓名序号2位][校验位2位]`；序号按**姓名拼音首字母**在同届、当次导入内分配；补录接着该届最大序号继续，**不重排已发码**；一次导入可混多届。
- 首页「社团概览」的**社员查询**：按真实姓名 / 社员编号查，结果卡与扫码校验页同一组件，只给姓名 / 届数 / 状态 / 识别码 / 头像。
- 查询按查询者身份分档限次：未登录 3 次、已登录未认证 10 次、已认证非社员 20 次；社员 / 认证教师 / 管理员不限（滚动 24 小时，未命中同样计数）。
- **我的设备**：绑定社员身份后，个人中心「我的设备」可登记能带到社团活动使用的物品——只填物品名（1–100 字），每人最多 30 项，可改名 / 删除；仅本人与管理员可见。后台在「账户 → 社员设备」按届数 / 姓名 / 物品名查看。

## 3. 活动（`activities`）

「活动」是**星形结构**：中心向成员发起，成员各自交回票 / 作品 / 展品 / 答卷，参与者之间没有关系。四种类型：

| 类型 | 成员做什么 | 结算 |
|---|---|---|
| **众议** | 投一张选票（选 1..K 个自定义选项） | 截止后按选项计数，票数即结果 |
| **征集** | 交**恰好一个**作品（一束文件） | 发起人或复审者逐个判**录用 / 退稿**（可附评语） |
| **展示** | 对每个展品**点赞 / 点踩**（三态互斥、可改可撤、记名） | 可选叠加活动级投票 |
| **调研** | 答一份问卷（登录一次 / 访客按设备一次） | 统计在问卷后台 |

- **排期**：设开始时间 → 创建后「待开始」，到点惰性自动开放；不设则创建即开放。
- **期限**：可设截止时间，也可勾「长期有效」（不设截止、不因时间自动结束，只能由发起人或管理员手动终结）。
- **受众**：公开 / 仅成员 / 仅社员，创建时设定不可改，四种类型通用（调研=作答、众议 / 展示=投票、征集=投稿）。公开受众下未登录游客也能投票 / 作答，按**设备标识**一设备一张并留痕 IP（征集投稿仍需登录 + 已认证）；仅成员要求登录（调研作答只需登录，投票 / 投稿另需已认证）；仅社员另要求账号已绑定社员名册（已毕业 / 已退社也算）。
- **秘密投票**：可选，个人明细仅超管可见；默认公开明细。
- **展品**：策展人在待开始 / 展示中布展（自上传，或从征集勾选作品导入为快照）；改标题仅限待开始，已结束不可再动。
- **列表排序**：未结束在前、已结束沉底，同档按发布时间倒序（后发布在上）。

## 4. 重大活动（`events` 壳）

2026-11 起 `events` **不再提供通用活动 CRUD**（`/#/events` 页面与 `EventViewSet` 已下线），只保留 `Event` 壳与严格状态机，供形态模块使用。当前唯一形态是**明信片互寄**。

- `Event` 提供**壳**（标题 / 简介 / 正文 / 时间窗 / 状态 / 可见性）与状态机：`draft → scheduled → active → ended → archived`（[lifecycle.py](https://github.com/nhyzcms/club-management-website/blob/main/events/lifecycle.py)）。
- 具体形态放 `events/modules/<key>/`，由 `module_key` 指向；`module_key` 为空 = 纯展示型壳。
- 用户入口：明信片互寄 `/#/postcard`（主页 / 手机版首页「重大活动」）；不再有 `/#/events` 页面。

### 明信片互寄（`events/modules/postcard`）

首个活动形态，方案与进度见 `documentation` 分支的 `docs/plans/postcard-exchange.md`。用户页 `/#/postcard`（主页按钮新标签页打开），管理端 `/#/postcard/admin`，签收页 `/#/postcard/receive`。

**活动阶段**：未开始 → 登记中 → 已寄出 → 下发中 → 已结束，由管理员配置的节点时间**惰性推导**；仅「登记中」开放登记，其余阶段只读公告与进度条。

**登记**：

- 扫码 / 手输 **7 位 Code128 条码**（管理员预生成 1500~10000 张、步进 500，A4 整版 PDF 40×20mm、间隙 2mm 供裁切，活动内不重复）。
- 正反面照片：魔数校验、重编码**默认压缩**（最长边 1280 / 质量 80）并去 EXIF、私有存储。
- 姓名 / 年级 / 班级 / 寄达区 / 寄达校下拉；寄达区为**上海 16 区固定清单**，寄达校按区从管理员配置的学校清单过滤，校验要求区校配对命中。
- 归属识别 = 设备 Cookie + 轻量指纹哈希 + 登录用户三轨。

**登记码**：AI 审核**通过才在「登记成功」弹窗亮 6 位登记码**；AI 不可用或转人工复核时立即亮码；判定不匹配则不发码、告知具体错项，用户可申请人工复核。6 位码即能力凭证：任何设备凭码可查 / 改 / 取消。**同一发件人（姓名 + 年级 + 班级）多次提交共用同一个登记码**，每次独立审核。

**AI 审核**（OpenAI 兼容协议，urllib 零依赖）：管理员后台配 base_url / api_key（**写后不可读**，GET 只回掩码）/ 模型 ID（支持 DeepSeek / OpenCode-GO 快捷预设，模型清单从服务商 `/models` 实时拉取）/ **温度（0–2，默认 0）** / 自定义请求头 / 超时 / **动漫黑名单 IP 清单（默认 38 条）** / **前置提示词**（多行，每次请求并入首条 system 消息，带默认文案）；Base URL / 模型 ID / 超时 / 自定义请求头收在「高级选项」折叠区。**所有管理端 AI 端点**（测试连接 / 模型清单 / 读样例 / 导入海报 / 模拟判定）都用当前填写的草稿参数（不落库）。活动开始前必须上传**填写样例**，否则登记不开放。后台线程审（Semaphore 限并发，不挂起 worker），前端轮询拿结果；1 次初始 + 5 次重试（指数退避）全失败自动转人工，**连续 5 个不同用户**失败邮件告警所有绑定邮箱的管理员（1h 冷却）。

**照片生命周期**（`lifecycle.py`）：AI / 人工通过立即删文件（行保留记终态）；审核失败且用户关标签页走 `sendBeacon` 删 + TTL 兜底；活动结束全量清除（状态翻转惰性触发 + `postcard_photo_gc`，安装脚本会装 `*-postcard-gc.timer` 每小时兜底）。登记数据永久保留。

**管理端**六个分区：活动配置（含富文本公告与 Word 导入、公告 PDF）、条码（生成 / 整版 PDF）、AI 配置与填写样例（含高级选项 / 温度 / 前置提示词 / 默认黑名单、「测试连接」与服务商预设）、登记记录（搜索 / 改 / 取消 / 删除 / xlsx、pdf 导出，含公式注入防护）、统计（指标卡 + chart.js 图表按需加载）、建议与审计；支持**多届活动**（开启新一届自动归档并新建草稿，AI 配置继承但清空 API Key）；Django 后台另有「明信片配置」年度批次只读一览 + 整批删除（含照片 / 登记 / 条码 / 审计，不可恢复）。提供**模拟环境**（前端内存沙箱，管理端 + 用户端 + 复核 + 签收全链路演练，AI 可真跑但不落库）。人工复核并入全站审核台 `/#/reviews` 的「明信片」桌，新申请按现有站内信规则通知管理员（同登记码未读合并，防刷屏）。

## 5. 问卷系统（[ADR-0014](adr/0014-questionnaire-independent.md)）

SurveyJS 问卷本体独立于活动：**发起活动时即可设计**，创建后也能补题、作答、按作答内容检索、统计与导出；支持 panel 与选项内子题。调研活动只是作答入口，问卷后台才是阅读与导出入口。规则见 [问卷指南](guides/surveys.md)。

## 6. 内容

- **新闻**：富文本正文、封面上传、编辑器插图，发布走审核。
- **教程**：上传与审核。
- **关于页**：固定五块富文本（关于社团 / 关于一中 / 关于网站 / 联系我们 / 校园一览）+ 社团概览，不按块拆权限（`about.manage_aboutpage`）。
- **校园全景图**（[ADR-0022](adr/0022-campus-panorama-library.md)）：等距柱状全景入库时自动切多级瓦片 + 低清预览，浏览侧只吃瓦片（避开移动端 GPU 纹理上限）；支持 DJI Fly / DJI GO 4 球面全景与 zip 导入。
- **站点政策**：`GET /site-policy/` 下发运行时策略的公开子集，前端据此开关功能（[ADR-0010](adr/0010-runtime-site-policy.md)）。

## 7. 协作

- **任务**：可指派负责人与协作者，状态机 `待处理 → 进行中 → 待验收 → 完成 / 取消`；带标签。
- **评论区**（宿主为新闻 / 活动 / 任务）：三态 `open` / `muted`（已有评论可见、不能再发言）/ `closed`（仅协管可见）；嵌套上限、**3 分钟撤回**、墓碑删除（[ADR-0016](adr/0016-comment-thread-vs-dm.md)）。
- **私信**：1:1 会话，与评论区分离；App 壳收到原生 WS 新消息时派发 `club:unread` 常量事件驱动红点。
- **意见反馈**：提交后进入审核台「意见反馈」桌。

## 8. 审核（[ADR-0017](adr/0017-unified-moderation-system.md)）

统一的一套队列，桌面 `/#/reviews`，手机 `/#/m/review`。共六张桌：

| 桌 | 处理什么 |
|---|---|
| 身份 | 学生 / 教师身份认证申请（人工通道） |
| 密码重置 | 忘记密码的手动重置申请 |
| 内容 | 新闻 / 活动 / 教程发布送审（三张子桌共用一条队列） |
| 意见反馈 | 用户反馈 |
| 举报案 | 评论 / 内容举报；成立时按对象执行默认处置（内容下架 / 评论墓碑 / 全站禁言） |
| 明信片 | AI 判定不匹配的登记复核（双面照片 + AI 结论 + 通过 / 不通过 + 备注） |

各桌共用同一套「下一条」流转；取数规则在 `frontend/src/utils/reviewDesk.ts`，两端共用、勿复制。流程细则见 [审核系统指南](guides/moderation.md)。

## 9. 通知与运营

- **站内通知**：按来源可开关；未读红点 30 s 轮询 + 窗口可见 / 聚焦刷新。
- **横幅公告**、**全站禁言**。
- **全站弹窗公告**（[ADR-0042](adr/0042-site-wide-popup-announcement.md)）：后台发布 → 登录即弹窗；可导入 PDF / Word 并**按原排版渲染**（pdf.js / docx-preview，不转站内富文本）；受众可选全站 / 注册用户 / 认证用户 / 认证社员 / 管理员；可选同步发邮件到已认证邮箱；关闭即已读（服务端台账），后台可看已读人数 / 阅读率 / 逐人明细。
- **有效期群发**：`manage.py send_validity_broadcast`（支持 `--dry-run`）。

## 10. 考试看板（[ADR-0018](adr/0018-exam-board-batch-and-public-ws.md)）

一场考试 → 若干批次 → 若干科目场次；职员发布**题目误刊**后经公开 WebSocket `/ws/exam-board/` 广播到所有打开的看板。HTTP 读写：课表与授时匿名可读、持权可写。按**教室大屏**设计，手机端只给管理员「考试日程编辑」，不渲染看板本体。看板娘 / 提示音 / 语音播报三项默认全关。

## 11. 移动端与 App 壳

- **独立手机版** `/#/m`：底部 tab + 铃铛未读红点；「我的」按权限分「工作 / 常用 / 更多」，别处能到达的入口不重复列。
- **手机版工作台**：`/#/m/review`（审核台）、`/#/m/inbox`（待办）、`/#/m/notifications`、`/#/m/tasks`。
- **UA 自动改道**：手机 UA 打开 `/reviews`、`/inbox`、`/notifications`、`/tasks`、`/events` 等桌面路径自动 `replace` 到等价 `/m` 页面；`/v`、`/feedback` 不跳转，页面内按 UA 切换版式。
- **深色模式**：浅色 / 深色 / 跟随系统；深色底色纯黑 `#000`（OLED 省电），卡片靠 `--bg-soft` / `--surface-2` 保留层次。
- **App 壳契约**：UA 注入 `NhyzClubApp/<versionName> (Android; <versionCode>)`；低于 `MIN_SHELL_VERSION_CODE` 时全屏提示更新（可「暂时继续」）；「关于 APP」页 `/#/m/about-app` 只在壳内可达。
- **SPA 入口不缓存**：`/` 与兜底路由用 `never_cache` 包裹，否则 WebView 拿着旧哈希要已删除的 chunk 会白屏。

## 12. 后台与运维

- **后台管理**：Django Admin + 自定义视图 + 前端 SPA。前端入口只对 `is_staff` 显示（`canAccessAdmin`），普通用户手输 `/admin/` 被挡回登录页。
- **一键部署**：`scripts/install.sh`（生成 SECRET_KEY、写 FRONTEND_URL、建超管、装 systemd 单元与明信片 GC timer）。
- **更新与回滚**：GitHub Release + 更新守护进程（维护页 / `scripts/updater.py --apply-now <sha>`），apply 前自动做 DB 快照（SQLite `backup` / PG `pg_dump`），失败回滚。
- **维护模式**：`manage.py maintenance on / off / status`（写 `run/MAINTENANCE`）。
- **运行时旋钮**：五张单例策略表（Auth / RateLimit / Upload / Updater / Content，[ADR-0046](adr/0046-site-settings-split.md)），后台可改、免重启。
- **统一数据根**：`media/`、`private_media/`、`data/` 的布局与换根剧本见 [统一数据根](operations/data-root.md)。
