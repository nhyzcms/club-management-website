# 账号与安全中心

> 相关：[账号 API](../api/accounts.md) · [安全验证（Step-up）](security-verification.md) · [访问控制](access-control.md) · [ADR-0028](../adr/0028-multi-device-login.md) · [ADR-0029](../adr/0029-account-security-center.md)

「账号与安全」是把改密、安全问题、登录方式、登录设备与登录记录收在一处的页面：**`/#/security`**。它替代了个人主页里原有的「安全验证 / 修改密码 / 登录记录」三个标签页——旧链接会 `replace` 到新页，不会 404。

页面分两块：

- **证明你的身份的方法**：密码、邮箱、安全问题、通行密钥（Passkey，待域名 + HTTPS）、滚动密钥（TOTP）、恢复代码；
- **登录与设备**：最近一次登录城市的地图打点、当前/其他设备列表、登录记录（分页 20 条）。

## 身份证明方式

| 方式 | 绑定 / 启用 | 用途 | 备注 |
|---|---|---|---|
| 密码 | 注册时设置，可在安全中心修改 | 登录 + 敏感操作 | 改密需原密码 + 安全验证 |
| 邮箱 | 在「账号认证」绑定并点邮件确认 | 登录、找回密码、接收验证码 | 只有**已认证**邮箱算账号邮箱 |
| 安全问题 | 安全中心设置 1–3 题 | 安全验证（敏感操作） | 首次设置需登录密码；答案只存哈希 |
| 滚动密钥（TOTP） | 扫码或手输密钥 → 6 位码确认 | 陌生设备登录 + 安全验证（管理动态口令时除外） | 最多 5 个，每个独立 secret |
| 恢复代码 | 首次确认 TOTP 时自动生成 | 登录验证 + 安全验证（含解绑动态口令） | 10 个一次性码，只存哈希 |
| 通行密钥（Passkey） | 待启用 | — | WebAuthn 的 RP ID 不能是 IP，须域名 + HTTPS；当前站点不满足 |

「安全验证（Step-up）」与登录二次验证是两套机制（触发场景不同），但**共用同一套验证方式**（[ADR-0043](../adr/0043-stepup-factor-registry.md)）：动态口令 / 邮箱验证码 / 安全问题 / 恢复代码都能用。唯一例外是「管理动态口令」本身（解绑滚动密钥 / 重新生成恢复代码）不能用动态口令验证——丢手机时它救不了你，请改用邮箱验证码、安全问题或恢复代码。

## 设备与信任原则

**设备身份 = 服务端签发的随机 ID**（`club_device` Cookie，HttpOnly、2 年），与硬件标识无关。浏览器没有任何 API 能读 MAC；品牌 / 型号只能从 UA 与 User-Agent Client Hints 尽力推断：

- Android Chromium：UA 可能带机型（如 `SM-S918B`），服务端下发 `Accept-CH` 后还能拿到 `Sec-CH-UA-Model`；
- iOS Safari：只能到「iPhone / iPad」，拿不到具体型号；
- Windows / macOS 桌面：只有系统与浏览器，**没有品牌型号**。

因此设备行允许只显示「Chrome · Windows」；**MAC 地址在 Web 端不可得**，模型里的 `mac_address` 字段只预留给未来的原生客户端。

**信任原则（2026-10-24 定）：所有设备初始都是陌生设备；信任的唯一来源，是该设备上完成过一次有效的二次验证。** 指纹、IP、地理位置都不构成信任。

- 清 Cookie / 换浏览器 = 设备回到陌生，下次登录重新验证；
- 设备被用户撤销后回到陌生态，下次登录重新验证；
- 登录名额与设备信任相互独立：同一账号最多 **3 台设备同时保持登录态**（[ADR-0028](../adr/0028-multi-device-login.md)），名额满时顶掉最久未活动的那台，被顶设备收到 `session_superseded`。

## 陌生设备登录挑战

密码正确后，服务端按 `(账号, 设备 ID)` 找设备记录：

```
密码正确
├─ 设备已验证（trusted）──────────────→ 直接建立会话
└─ 设备陌生
   ├─ 账号有可用二次验证方式 ─────────→ 202 + challenge（不建会话）
   │    └─ 通过 TOTP / 邮箱码 / 安全问题 / 恢复代码任一
   │         → 建立会话 + 设备 trusted_at=now
   └─ 账号没有任何二次验证方式 ───────→ 本次豁免放行（must_bind_2fa=true）
        → 设备仍保持陌生；前端跳 /#/security?bind=1 提示尽快绑定
```

**202 响应**（`POST /auth/login/`）：

```json
{
  "challenge": "<一次性令牌>",
  "methods": ["totp", "email", "question", "recovery"],
  "questions": [{"id": 1, "text": "…"}],
  "reason": "new_device",
  "expires_in": 600
}
```

- `methods` 只列该账号**真正可用**的方式，顺序为 TOTP → 邮箱码 → 安全问题 → 恢复代码；邮箱方式的键是 `email`（上线前的旧挑战可能仍存 `email_code`，服务端按同义值兼容）；
- 挑战令牌 10 分钟有效、最多失败 5 次，失败次数用尽需重新登录；
- 邮箱码需先调 `POST /auth/login/challenge/` 发信（60 秒冷却）；
- 通过 `POST /auth/login/challenge/verify/` 提交后建立会话；若账号被管理员重置过密码，响应仍带 `must_change_password=true`。

**豁免不等于信任**：没有任何二次验证方式的账号本次放行，但设备保持陌生，下次登录仍会要求；页面顶部横幅提示绑定，绑定任意一种方式后下次登录即进入挑战。

**应急开关**：`LOGIN_CHALLENGE=0` 关闭陌生设备挑战（设备与登录事件照常记录）；`manage.py test` 下自动关闭，挑战流程由单测用 `override_settings` 单独打开。

## 滚动密钥（TOTP）与恢复代码

- 算法 RFC 6238：HMAC-SHA1、30 秒、6 位，兼容 Google / Microsoft Authenticator；
- 校验允许 ±1 个时间窗（时钟漂移），每条记录用 `last_used_step` 防重放；
- secret 用 Fernet 加密入库（密钥由 `SECRET_KEY` 派生），明文只在 setup 响应里出现一次；
- 每个账号最多 5 个滚动密钥，每个独立 secret / 独立名称；
- 解绑单条、重新生成恢复代码都需 **Step-up**（`X-StepUp-Grant`，scope `manage_totp`；**验证时不能用动态口令本身**，需邮箱验证码 / 安全问题 / 恢复代码）；解绑最后一个时页面会明确提示「账号当前没有 TOTP 二次验证」；
- 恢复代码账号级一组 10 个，只在首次确认 TOTP 时自动生成，之后需手动重新生成；重新生成会作废旧码，明文只返回一次，库中只存 sha256。

## 登录记录与地图

`GET /auth/login-events/` 返回本人登录流水（20 条/页），字段含时间、设备名、城市 / 省份 / 国家、经纬度、登录方式、结果、二次验证方式、是否新设备、脱敏 IP（`123.45.*.*` / IPv6 前缀）。

- 结果 `status` ∈ `success` / `failed` / `blocked` / `challenge`；
- 二次验证 `second_factor` ∈ `totp` / `email` / `question` / `recovery` / `none`（无挑战）/ `exempt`（无 2FA 豁免）；`email` 的旧记录可能为 `email_code`；
- 位置由离线 **ip2region** 库解析到**城市级**，坐标取内置城市中心点表；移动网络常落到运营商出口城市（可能显示省会），IPv6 精度更差；
- 页面固定标注「根据 IP 推算，仅供参考」，不提供街道级位置；
- 地图用高德 JS API：构建时 `AMAP_KEY=… npm run build` 注入；未配置 key 或脚本加载失败时降级为城市文字，不阻塞页面。

## 管理端（只读 + 留痕）

Django Admin 的「账户」下新增三张只读表：

- **登录事件**（`LoginEvent`）：全部账号的成功 / 失败 / 待验证 / 被限流记录，可按结果、方式、二次验证、新设备、城市过滤，搜索用户名 / 邮箱 / IP / 城市 / 设备；
- **账号设备**（`AccountDevice`）：设备名、平台、最近城市、最近活跃、信任时间、撤销时间；**信任状态只由二次验证写入，后台不提供手改**；
- **管理端访问记录**（`AdminAccessLog`）：谁在何时从哪个 IP 查看了登录记录 / 设备列表，`scope` ∈ `login_events` / `devices`。

三张表都不提供新增 / 修改 / 删除。**查看即留痕**：打开登录事件或设备列表的 changelist 就会写一条 `AdminAccessLog`（带被查看账号时记录 `target`）。

## 已知边界

- **拿不到 MAC 地址**；品牌 / 型号为尽力推断，桌面与 iOS 通常为空；
- **定位只到城市**，不提供街道级 / GPS 精度；
- **Passkey 暂不可用**：RP ID 必须是域名（Chrome / Firefox 拒绝 IP），需要域名 + HTTPS 后才能上；
- **没有短信验证码通道**；
- 动态口令不能用于「管理动态口令」自身的 Step-up（解绑 / 重生成恢复代码）——防止「拿到设备 + 密码」就能拆掉受害者其余验证方式；此场景用恢复代码 / 邮箱验证码 / 安全问题；
- 登录事件暂无自动清理任务，保留期策略待定。
