# 身份认证

> 相关：[账号 API](../api/accounts.md) · [访问控制](access-control.md) · [ADR-0006](../adr/0006-verification-model.md) · [ADR-0013](../adr/0013-appointment-verification-channel.md) · [ADR-0020](../adr/0020-authcode-verification-channel.md) · [ADR-0023](../adr/0023-email-domain-allowlist.md) · [ADR-0025](../adr/0025-member-identity.md)

## 为什么要认证

注册与认证**分离**：任何人都可注册（用户名 + 密码 + 真实姓名 / 身份 + Turnstile 人机验证，邮箱可选），但新账号默认是**访客**，功能受限；通过任一认证通道后才成为正式「用户」。

- 认证是**身份态**，不是权限：它不授予任何具体能力（能力仍由组 → 权限分配，见 [访问控制](access-control.md)）；它只把账号从「访客」提升为「用户」，放开各模块中标注「已认证」的端点（如任务认领、活动参与）。
- **未认证也可以登录**——认证不卡登录，只卡「参与 / 写操作」。

## 核心模型：任一通道通过即「已认证」

```
账号「已认证」 ⇔ 至少一条认证通道 approved 且未过期
```

- `Verification(user, channel, status)`：每 `(用户, 通道)` 一行，状态 `pending / approved / rejected`，就地更新；存在**未过期**的 `approved` 行即 `is_verified = true`——过期通道不再算数，账号回落访客、可重新认证。
- **单一认证路径**：任一条通道通过后，认证面板上其余通道一律显示为「无需再次认证」并收起申请表单——只需走通一条，不必也不应把每条都走一遍。该状态是端点**读取时计算**的派生态（`not_required`，不落库、不进 choices）：认证过期、账号回落访客后，其余通道自动恢复可申请状态；邮箱通道例外地保留折叠的「绑定邮箱」入口（仅用于登录 / 找回密码，不影响已完成的认证）。
- 人工通道的证据（`IdentityProof`）**永久留底**，审核通过或重新提交都不删除。
- 人工通道驳回后**允许重交**：通道行回到 `pending`，新证明累加。

### 四条通道

| 通道 | 触发方式 | 说明 |
|---|---|---|
| `manual` 人工审批 | 用户提交身份证明 → 信息组审核 | 主通道：真实姓名 + 证明件上传 |
| `email` 邮箱 | 用户自助绑定 → 点邮件链接确认 | 认证通过才把地址晋升为账号邮箱；**仅支持白名单内的邮箱后缀**（见下） |
| `appointment` 后台委任 | 账号被授予 `is_staff` / `is_superuser` 时**自动** approved | 只读、无自助申请；撤销委任则删行、退回未认证 |
| `authcode` 认证码 | 管理员在后台生成码 → 成员在面板兑换 | 线下分发；码带有效期 + 可用次数，兑换即通过、无人工环节；过期 / 吊销不回溯已通过者（[ADR-0020](../adr/0020-authcode-verification-channel.md)） |

> 管理员 / 超级管理员不走自助流程——委任本身就是一条认证通道（[ADR-0013](../adr/0013-appointment-verification-channel.md)）。注意认证轴与权限轴的「逃生舱」相互独立：超管的 `has_perm` 恒真（[ADR-0005](../adr/0005-access-control-principle.md)），而认证面板照常显示其「后台委任」通道状态。

### 认证有效期与到期

认证不是一劳永逸：通道通过时会记下**有效期至**（`expires_at`），到期后该通道不再算数。

| 期限 | 站点设置 | 默认 | 说明 |
|---|---|---|---|
| 认证有效期 | `verification_valid_days` | 365 天 | 认证通道（邮箱 / 人工 / 认证码）通过后的有效期。到期后账号回落为访客，重新走任一通道即可再次认证；认证码到期后可用新码重新兑换。 |
| 管理员身份有效期 | `admin_valid_days` | 730 天 | 后台委任通道的有效期。到期后系统自动撤销 `is_staff`（回落普通用户，需重新授予）；超级管理员不受限（永久）。 |
| 注册后认证宽限 | `registration_verify_days` | 60 天 | 注册后**从未认证**的宽限。超期账号被自动停用（`is_active=False`），登录时收到专属提示（`account_expired_unverified`），需联系社长 / 服务器管理员处理。 |

- 执行方式：登录时即时检查；请求时**惰性执行**（处理当前账号，按会话节流、默认 5 分钟内至多一次）。另有 `uv run python manage.py enforce_validity [--dry-run] [--skip-notices]` 供 cron / 定时器兜底：先做降权 / 停用，再发下一条的到期前提醒（`--skip-notices` 可只跑前者）。
- 三个期限在 Django admin「站点策略」调整；单个用户的「注册认证截止」可由持 `accounts.manage_validity` 权限者显式延 / 缩（见下「管理员视角」）。

#### 到期前提醒（降权预警）

到期会造成**降权**的两类身份，会在到位前自动提醒一次：

| 档位 | 触发 | 站内通知事件 |
|---|---|---|
| 还剩两个月 | `expires_at` 落在未来 60 天内 | `expiring_2m`（源「身份有效期」）|
| 还剩一个月 | `expires_at` 落在未来 30 天内 | `expiring_1m`（源「身份有效期」）|

- 覆盖范围：认证通道（已认证 → 未认证）与管理员委任通道（撤销 `is_staff`）。超管委任 `expires_at=null`（永久）永不提醒；「注册后未认证会被停用」不在提醒范围内（那是停用，不是降权）。
- 文案带通道与到期日（如「管理员身份 · 2026-12-11 到期」），点通知直接落到认证面板；**只发站内**，用户可在「个人中心 → 通知设置」里退订该源（或自行开启邮件）。
- 幂等：台账 `ValidityNotice`（通道行 × 到期时间 × 档位）保证每个档位只发一次；同一到期时间只发**最紧迫**的那一档——首次扫描时如果只剩 20 天，就只发「还剩一个月」，不补发已经无意义的「两个月」。到期时间被改写（续期 / 重新委任）后重新起算。
- 发送时机：与降权执行同批（`manage.py enforce_validity`，建议 cron / systemd timer 每日跑）；用户若关闭了该源的站内通道（拒绝接收）则不落账，重新开启后仍能收到。

#### 有效期说明弹窗与群发私信

- **弹窗**：前端在登录态变化（注册成功即登录）与认证动作成功后各拉一次 `GET /auth/validity/`，若 `notice_pending` 就弹「账号有效期」——**到期时间、剩余有效期、三条规则**（天数取站点设置实时值）。点「我知道了」把快照键写回 `Profile.validity_notice_ack`（存服务端，跨设备一致），同一状态不再重复弹；续期 / 重新认证后键变化，会再弹一次。人工认证由管理员审核通过时用户不一定在线，下次进入站点即可看到。
- **认证面板**：面板顶部同时显示「账号有效期至 / 剩余 N 天」或「认证截止时间」，随时可查。
- **群发私信**：`uv run python manage.py send_validity_broadcast [--dry-run] [--from <用户名>] [--limit N] [--dedupe-days 7]` 给全体启用用户发个性化站内私信（到期时间 / 剩余有效期 / 规则），并投一条「收到新私信」站内通知（未认证用户顶栏无私信入口，靠通知点进会话）。跳过发送者本人、已注销与停用账号；同一会话在 `--dedupe-days` 天内已发过同样消息的会跳过（防手滑重跑刷屏）。

## 用户视角

1. **注册** → 默认访客（无认证记录）。
2. 打开个人中心的**认证面板**（`GET /auth/verification/`）：数据驱动的通道状态卡，查状态、绑邮箱、提交证明都在这里。
3. **走邮箱通道**：`POST /auth/verification/email/bind/` 绑定地址 → 收到认证邮件 → 点链接确认（`/auth/verify-email/`）→ 通道 approved，地址晋升为账号邮箱。地址后缀须在白名单内（含校园邮箱），否则面板弹窗提示换用其他邮箱。
4. **走人工通道**：`POST /auth/verification/manual/submit/` 提交真实姓名 + 证明件 → 等待审核。
5. **走认证码通道**：收到管理员发放的认证码后，在面板输入并兑换（`POST /auth/verification/authcode/redeem/`）→ **即时通过**，无人工环节。
6. **结果**：通过 → 徽章变「用户」，受限功能放开；驳回 → 邮件通知，可重新提交。

> 没收到邮件可用 `/auth/resend-verification/` 重发；邮箱登录**只认已认证邮箱**，待认证地址登不进。

## 社员身份编号（名册认领）

学校各届社员名册导入后，每个名册行持有 8 位**识别码**（工牌二维码本体）；账号可绑定到自己的名册行（[ADR-0025](../adr/0025-member-identity.md)）。这是独立于认证通道的一条名册线：认证回答「账号是否可信」，它回答「你在名册里是谁」。

- **认领**：注册成功时，若名册中有与本人真实姓名匹配的未绑定行，注册页进入认领阶段（**手机号后四位**核验；可跳过，之后在个人中心「社员身份」补办）。绑定后识别码随时可查；重导名册保留既有绑定。**在校生 / 毕业生**注册时可**选填校牌号**（与名册「校牌号」同一个值）：姓名 + 校牌号与名册唯一命中时直接自动绑定；没命中（名册还没导入等）也不影响注册，名册导入时按姓名写回。
- **编号查询入口**：`/#/v` 支持摄像头扫工牌条形码（12 位签名载荷，匿名可查且**不消耗查询额度**）与手动输入（8 位识别码 / 真实姓名，按身份分档额度）。带 `?q=<内容>` 落地即自动查一次（`/#/v?q=260901667878`）——Android 客户端原生扫完条码/二维码后走这条深链接，网页端手动粘贴同一串也照样能用。
- **扫码校验**：工牌二维码指向 `/#/v/<识别码>?s=<签名>`（HMAC-SHA256 防枚举）——只显示姓名 / 届数 / 在册状态，**电话 / 校牌号 / 邮箱绝不下发**。发放与管理（名册导入 / 重匹配 / 解绑 / 二维码与条形码导出——条形码可出 PNG 或透明底 SVG）在 Django 后台「账户 → 社员身份编号」（见[管理后台指南](../operations/admin-guide.md)）。
- **社员查询**：首页「社团概览」可按**真实姓名 / 社员编号**查社员（姓名要求完整一致，不做前缀 / 模糊匹配）。结果卡与扫码校验页同一组件、同一份公开字段（姓名 / 届数 / 在册状态 / 识别码 / 头像，**不含电话 / 校牌号 / 邮箱**）；额度按查询者身份分档、滚动 24 小时——未登录 3 次、已登录未认证 10 次、已认证的非社员 20 次，社员 / 认证教师 / 管理员不限，**未命中同样计次**（防遍历）。接口见[账号 API](../api/accounts.md)。
- **开关与额度**：认领开关（默认开）与认领 / 扫码校验 / 条码载荷查询的限流在站点策略；关闭后认领接口 403 `claim_closed`、注册页不再展示认领阶段（已绑定不受影响）。接口见[账号 API](../api/accounts.md)。

## 邮箱后缀白名单

只接受成员普遍在用、发信到达率稳定的邮箱（[ADR-0023](../adr/0023-email-domain-allowlist.md)）；名单定义在 `accounts/email_domains.py`。

| 类别 | 允许的后缀 | 匹配方式 |
|---|---|---|
| 网易 | `163.com` · `126.com` · `yeah.net` · `188.com` · `vip.163.com` · `vip.126.com` | 精确 |
| QQ | `qq.com` · `foxmail.com` · `vip.qq.com` | 精确 |
| 微软 Outlook | `outlook.com` · `hotmail.com` · `live.com` · `live.cn` · `msn.com` | 精确 |
| Apple iCloud | `icloud.com` · `me.com` · `mac.com` · `privaterelay.appleid.com`（「隐藏我的邮件」转发地址） | 精确 |
| 中国移动 / 联通 / 电信 | `139.com` · `wo.cn` · `189.cn` · `21cn.com` | 精确 |
| 新浪 | `sina.com` · `sina.cn` · `sina.com.cn` · `vip.sina.com` | 精确 |
| 中国大陆院校 | `edu.cn` 及其子域（`pku.edu.cn`、`stu.pku.edu.cn`、`mails.tsinghua.edu.cn` …） | **后缀** |
| 香港 / 澳门 / 台湾院校 | `edu.hk` · `edu.mo` · `edu.tw` 及其子域（`link.cuhk.edu.hk`、`um.edu.mo`、`gm.ntu.edu.tw` …） | **后缀** |
| 学生信箱不在 `edu.*` 下的院校 | `hku.hk` · `ust.hk` · `polyu.hk` · `eduhk.hk` · `hksyu.edu` · `umac.mo` · `cityu.mo` · `ucas.ac.cn`（中国科学院大学） | **后缀** |

- **两类判定**：商业服务商域**精确匹配**（`notqq.com`、`163.com.evil.com` 不放行）；院校域**域自身或其子域**均放行 —— 高校邮箱无法穷举（一校一个域，学生信箱常在 `stu.` / `mails.` / `connect.` 等更深子域）。
- **拦哪里**：只在**接收新地址**的两处判定 —— 注册带邮箱（`/auth/register/`）与绑定 / 换绑（`/auth/verification/email/bind/`）。命中白名单外的后缀返回 400 `{"error": "该邮箱后缀暂不可用，请换用其他邮箱。详询社长或服务器管理员", "reason": "email_domain_not_allowed", "domain": "…"}`，认证面板据此弹窗提示。
- **不回溯**：已绑定 / 已认证的旧地址照旧有效；同一待认证地址的**重发**（面板「重发认证邮件」与 `/auth/resend-verification/`）与**认证链接落地**不校验后缀；Django 后台由管理员手填的邮箱也不校验。
- **未覆盖的自建域**（公司域、未列入的中科院各所 `@xxx.ac.cn`、部分自资院校）不在名单内：这类成员走人工审批或认证码通道完成认证；需要放开时改 `accounts/email_domains.py` 加一行。

## 管理员视角

- **审核队列**：`/auth/identity-reviews/`（列表 / 详情 + 三个动作：**通过 / 驳回 / 停用账号**），需权限 `accounts.can_review_identity`。
- **停用账号**是账号级处置：`is_active = False` + 吊销会话，与通道状态无关。
- 通过与驳回会发送邮件通知；所有动作在 Django Admin 中亦可操作。
- 审核用的证明文件经带鉴权的视图读取（`/auth/identity-proof/<id>/`），**不经**公开媒体路径。
- **有效期管理**：持 `accounts.manage_validity`（默认授予社长 / 信息组）者可对**下位**用户调整「注册认证截止」与认证通道「有效期至」（Django Admin 用户页内嵌「认证通道」表）；平级 / 上位不可改，超级管理员无人可改。

## 边界与细节

- **密码重置**发往已认证邮箱；没有绑定邮箱 → 在「忘记密码」页走「联系管理员」申请（上传身份证明 → 审核台「密码重置」桌批准），或联系信息组人工处理。
- **会话相关**（多端登录 / 名额顶替 / 登录保护，[ADR-0028](../adr/0028-multi-device-login.md)）属于会话层，与认证体系无关，详见 [API 总览](../api/README.md#错误格式)。
- 认证面板**仅本人可见**。
- 加新通道 = 加 `CHANNEL` 枚举 + 实现该通道流程，`is_verified` 判定自动纳入（[ADR-0006](../adr/0006-verification-model.md)）。
- **超管豁免**：超级管理员的委任通道永久有效（无到期日）；已停用账号不再被有效性执行重复处理。
